# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

This is the RPG Maker MZ project for **"Look Outside"** (`game.rmmzproject`, engine version 1.1.1). The directory is both the editable project *and* a runnable playtest build: it contains the full nw.js/Chromium runtime (`Game.exe`, `nw.dll`, etc.) alongside the editable `data/` and `js/` sources. There is no separate source vs. build tree — editing files here directly affects what runs.

There is no package manager, build step, linter, or test suite. This is not a Node/npm project (`package.json` only configures the nw.js window title/size — do not run `npm install` or expect scripts there). All "development" happens by:

- Editing database/map content in `data/*.json` (normally done through the RPG Maker MZ editor GUI; when hand-editing, preserve exact JSON structure/field sets that RPG Maker expects, since malformed data can crash the editor or the game on load).
- Editing plugin JS in `js/plugins/*.js`.
- Playtesting via `Game.exe` (the bundled nw.js runtime reads `index.html` → `js/main.js`).

## Architecture

### Engine layer (do not modify)
`js/rmmz_core.js`, `rmmz_managers.js`, `rmmz_objects.js`, `rmmz_scenes.js`, `rmmz_sprites.js`, `rmmz_windows.js`, and `js/libs/*` are the stock RPG Maker MZ engine and third-party runtime libs (pixi.js, effekseer, pako, localforage). Treat these as vendored/read-only.

### Plugin layer (`js/plugins/`)
Loaded in the order listed in `js/plugins.js` (auto-generated by the RPG Maker editor's Plugin Manager — the "do not edit directly" header is aspirational; if you hand-edit a plugin's parameters or enable/disable it without the editor, edit this array directly and keep the JSON-in-JS parameter strings well-formed). Two categories of plugin live side by side:

- **Third-party plugins** (CGMZ_*, GALV_*, HIME_*, TDDP_*, Mano_InputConfig, FilterControllerMZ, Cyclone-Steam, etc.) — standard RPG Maker MZ community plugins providing engine features (input config, steam integration, filters, battle systems). Treat as vendored; check the plugin's own header comment for its documented plugin commands/parameters before changing behavior.
- **Project-specific mod scripts** — the actual custom logic for this game: `bunchastuff.js` (largest file, ~6.6k lines, core custom game logic/events), `bunchastuff_old.js` (superseded/reference copy, likely not loaded — check `plugins.js` before assuming it runs), `DeepBasement.js` (procedural room/dungeon generation), `TemplateEvent.js`, `TunicateScripts.js`, `regenDamageResistFix.js`, `deleteNameInput.js`, `wordcountCalc.js` (currently disabled per `plugins.js`), `Scriptset2.js`/`Scriptset2.txt`, and `redact.js`.

### Global switch/variable helper convention
Custom scripts consistently use short global helpers instead of calling `$gameSwitches`/`$gameVariables` directly:

```js
gSw(switchId)        // $gameSwitches.value(switchId)
gVr(varId)           // $gameVariables.value(varId)
sSw(switchId, val)   // $gameSwitches.setValue(switchId, val)
sVr(varId, val)      // $gameVariables.setValue(varId, val)
```

These are defined redundantly in multiple plugin files (e.g. `bunchastuff.js`, `DeepBasement.js`, `Scriptset2.js`). When adding new custom logic, follow this convention rather than calling the engine APIs directly, and be aware switch/variable IDs are magic numbers tied to `data/System.json` — cross-check IDs there before reusing or repurposing one.

### `redact.js` — release sanitization script
Gated behind `Utils.isOptionValid("test")`, so it only runs when the game is launched with a `--test` flag (editor playtest mode). It rewrites `data/MapInfos.json`/`CommonEvents.json` (stripping `name`/`expanded` fields) and `data/System.json` (blanking switch/variable names, enabling audio/image encryption) into `*_new.json` sanitized copies — this is a pre-release step to strip developer-facing labels and internal names before shipping, not something that runs during normal play. Be careful not to trigger or rely on this when just testing gameplay changes.

### Save data
`save/*.rmmzsave` are live player save files (including `global.rmmzsave` config). Never overwrite or delete these as part of a task unless explicitly asked.
